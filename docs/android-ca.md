# Android trust anchor for the local JMAP CA

When a client app targets API 24+ (Android 7.0+), it does **not** trust user-installed CAs by
default. Install the local CA into the **system** trust store instead. This is needed for
clients such as Sterna Mail connecting to `https://localhost:8443/...`.

## 1. Identify the CA file

The CA certificate is `scripts/local-jmap-cert/ca.crt` (PEM, starts with
`-----BEGIN CERTIFICATE-----`), generated by
[`scripts/generate-local-jmap-cert.sh`](../scripts/generate-local-jmap-cert.sh). Its system-store
filename is based on the old-style subject hash:

```bash
openssl x509 -subject_hash_old -in scripts/local-jmap-cert/ca.crt | head -1
# e.g. 5bce0e25  ->  system filename 5bce0e25.0
```

Recompute this after every rebuild — the script generates a new CA.

> **Important:** `localhost` / `127.0.0.1` on the phone mean the **phone**. For Sterna to reach
> `https://localhost:8443/jmap/session`, the proxy must run on the device itself (e.g. inside an
> Ubuntu filesystem via proot/chroot). If the proxy stays on another machine, add a reachable
> hostname/IP to `scripts/local-jmap-cert/server.ext`, rebuild, and use that URL instead.

## 2. Android version behaviour

| Device / app | User CA import sufficient? |
| --- | --- |
| Android 6.x and older (API ≤ 23) | Yes |
| Android 7.0+ with an app targeting API ≤ 23 | Usually yes |
| Android 7.0+ with an app targeting API ≥ 24 (Sterna is modern) | No — system CA required |

Android 14+ stores system CAs in the immutable `com.android.conscrypt` APEX at
`/apex/com.android.conscrypt/cacerts`, not only `/system/etc/security/cacerts/`.

## 3. Rooted device — Magisk module (recommended, survives reboot)

- **Android ≤ 13:** install `ca.crt` as a user CA first (Settings → Security → Install from
  storage → CA certificate), then flash
  [NVISOsecurity/MagiskTrustUserCerts](https://github.com/NVISOsecurity/MagiskTrustUserCerts)
  in Magisk and reboot. The module copies user CAs into the system store at boot.
- **Android 14+:** use a Conscrypt/APEX-aware module, e.g.
  [Fox IT "Conscrypt Trust User Certs"](https://www.fox-it.com/be/tool-release-magisk-module-conscrypt-trust-user-certs/)
  or the `adguardcert` / `cert-fixer` approach. Install `ca.crt` as a user CA first, flash the
  module, reboot.

## 4. Rooted device — manual system install (Android ≤ 13)

Requires a rooted device and `adb` on the host.

```bash
HASH=$(openssl x509 -subject_hash_old -in scripts/local-jmap-cert/ca.crt | head -1)

adb push scripts/local-jmap-cert/ca.crt /sdcard/$HASH.0

adb shell
su

# Android 9 and older usually: mount -o rw,remount /system
# Android 10+ (dynamic partitions): remount root instead:
mount -o rw,remount /

mkdir -p /system/etc/security/cacerts
cp /sdcard/$HASH.0 /system/etc/security/cacerts/$HASH.0
chown root:root /system/etc/security/cacerts/$HASH.0
chmod 644 /system/etc/security/cacerts/$HASH.0
chcon u:object_r:system_file:s0 /system/etc/security/cacerts/$HASH.0 2>/dev/null || true

mount -o ro,remount /
exit
exit
adb reboot
```

If `adb root` works, you can use `adb remount` instead of the manual `mount` commands. Some
devices require disabling verified boot (`fastboot flashing unlock`, `adb disable-verity`,
`adb remount`) before `/system` is writable.

## 5. Android 14+ without a module

Direct writes to the APEX are not possible. The root-only workaround is a tmpfs over
`/system/etc/security/cacerts` plus bind mounts into Zygote and running app mount namespaces.
It is **not persistent across reboot**; prefer a Magisk module for long-term use. Full method:
<https://httptoolkit.com/blog/android-14-install-system-ca-certificate/>.

## 6. Verify

1. Settings → Security → **Trusted credentials** → **System** tab → look for the CA subject
   (`CN=Local JMAP Dev CA` in the generated example).
2. `adb shell su -c 'ls -l /system/etc/security/cacerts/<HASH>.0'`
3. Force-stop and reopen the client, then connect to `https://localhost:8443/jmap/session`
   (the proxy must run on the device for `localhost` to mean the device).
4. If you still get a hostname error, the URL does not match a SAN — use `localhost` or
   `127.0.0.1`, or add your hostname to `scripts/local-jmap-cert/server.ext` and rebuild.

## 7. Security notes

- A system CA is trusted by **every app** on the device. Remove the file after testing:
  ```sh
  adb shell su -c 'rm /system/etc/security/cacerts/<HASH>.0; reboot'
  ```
- Keep `scripts/local-jmap-cert/ca.key` private — anyone holding it can issue certificates the
  phone trusts.
- Rebuilding the certificate changes the CA; repeat the install with the new hash.
